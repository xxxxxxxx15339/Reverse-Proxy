In Go, Channels are the pipes that connect concurrent Goroutines. They allow you to send values from one thread to another without external locks or race conditions.
  1. The Core Concept: The Baton Handoff 
      Think of an unbuffered channel as a relay race baton handoff 
        * The Rule: The handoff cannot happen unless BOTH runners are at the same spot at the same time. 
        * Sender: If I try to hand you the baton (ch <- data), I must wait (block) until you are ready to grab it. 
        * Receiver: If you try to grab the baton (data := <- ch), you must wait (block) until I arrive to give it to you. 
      The blocking is a feature not a bug, It forces two independent threads to synchronize perfectly at a specific moment in time. 
  
  2. Basic Syntaxe ("The Arrow"): 
    The arrow <- shows the direction of the data 
      * Example: 
        """
          package main 
          import "fmt"

          func main() {
            // 1. Make the pipe (holds strings)
            // "Unbuffered" means no storage space inside the pipe itself.
            messages := make(chan string)

            // 2. Start a background worker 
            go func() {
              fmt.Println("Worker: Sending message...")
              messages <- "Ping!" // BLOCK here until main() is ready to Receive 
              fmt.Println("Worker: Sent!")
            }()

            msg := <- messages 
            fmt.Println("Main: Received", msg)
          }
        """

  3. Buffered Channels (The "Mailbox")
    Sometimes you don't want to stop working just because the other person isn't ready. You can add a "buffer" (storage capacity).
    * Code: make(chan string, 3) (Capacity = 3)
    * Behavior: 
      [Sending: You can send 3 items without blocking. The 4th send will block until someone empties a slot.]
      [Receiving: You can read quickly until the buffer is empty.]
